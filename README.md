# 💎 Amazon Diamond Hunter FREE — four-market candidate scout

## Обновление: все товары от -25%, Amazon/Cdiscount/Joybuy

Прямая охота на **все разрешённые товары от 25%** без приоритетов по брендам и категориям; одежда, настолки, Xbox и Samsung (кроме SSD) исключены. Для Cdiscount и Joybuy добавлен отдельный `retailer_direct.py` (не Dealabs). Ссылки и цены получаются исключительно от самих площадок, данные с чужих скидочных форумов запрещены в `RETAILER_ONLY=true`. Обычное расписание GitHub Actions не гарантирует фиксированный интервал, для более надёжного опроса предусмотрен постоянно работающий `fast_hunter.py`.

**Joybuy**: прямая витрина /marketing/lightning-offers, извлечение цен/исходных цен из одной карточки, проверка адреса товара. Проверяются до 6 разных карточек товаров за одно сканирование с интервалом не чаще раза в 10 минут; лимит Cdiscount остаётся отдельным. Если PDP не раскрывает цену (нет JSON-LD) или недоступна, допускается только однозначная цена/исходная цена из той же карточки витрины, явно помеченная как **непроверенная цена витрины**, с требованием перепроверить корзину. Некоторые предложения доступны только новым клиентам, поэтому условия надо читать у магазина.

**Cdiscount**: собственные категории и поиск; обычные GitHub-серверы получают от магазина страницу без товаров. Поддерживается *дополнительный* Bright Data Web Unlocker API (не Amazon dataset). В Bright Data надо создать Web Unlocker zone и добавить в [GitHub Actions Secrets](https://github.com/makeevmua/amazon-diamond-hunter/settings/secrets/actions) `BRIGHTDATA_UNLOCKER_ZONE` вместе с существующим `BRIGHTDATA_API_TOKEN`. Без настроенной зоны платных запросов на разблокировку нет, а Cdiscount может оставаться с нулём карточек. С настроенной зоной — не более **8 попыток Cdiscount в день**, чтобы не расходовать бесплатный пакет без ограничений. Этот лимит — лишь ограничение нашего кода; в кабинете Bright Data дополнительно настройте лимит расходов. Адаптер готов, но до проверки реальной цены с таким доступом нельзя обещать рабочие объявления Cdiscount.


## Только Amazon / Cdiscount / Joybuy — строгий товарный режим

**В продакшене включён `RETAILER_ONLY=true`.** Никаких объявлений Dealabs, mydealz, Chollometro, Brickset, Les Numériques и других источников в Telegram и на сайте. Удаляются ранее сохранённые карточки из базы без прямых магазинных цен, чтобы одежда Bonobo и настолки не оставались в каталоге. Запрет распространяется на одежду, обувь, моду, настольные и карточные игры; **LEGO, PS/PC/Nintendo, SSD и электроника остаются**.

Требуется точный URL товарной страницы по адресу Amazon.fr/de/es/it, Cdiscount.com или Joybuy.fr; категории магазинов, поиск, сторонние редиректы и ссылки на Dealabs не принимаются. Фотография и рекламный процент сами по себе не доказывают скидку. Для Amazon есть самостоятельные источники Keepa, Bright Data и Creators, работающие только с соответствующими ключами. **Joybuy уже сканируется напрямую; Cdiscount также подключён программно, но из-за ограничений доступа требует отдельной Bright Data Web Unlocker zone и реальных проверок, прежде чем можно говорить о стабильных находках.** Мы не выдаём страницу Dealabs за собственный мониторинг Cdiscount.

Для обратной совместимости локальных тестов без явной переменной окружения исторические механизмы доступны, но оба production-задания GitHub Actions всегда выставляют `RETAILER_ONLY=true`. Настройка собственного постоянно работающего контейнера также должна задавать `RETAILER_ONLY=true`.


## Bright Data Search — асинхронный режим

Поиск товаров Bright Data требует документированный `POST /datasets/v3/trigger` с JSON-массивом. Создаётся **не более одного оплачиваемого поискового задания в сутки по умолчанию**, результаты сохраняются как идентификатор `snapshot_id` и проверяются `GET /progress/` на будущих сканированиях без второго запуска поиска. После статуса `ready` товары загружаются через `GET /snapshot/`, фильтруются по Amazon.fr/de/es/it, времени и разрешённым категориям. Ошибки теперь сообщают только безопасный HTTP-код, без токена и тела ответа. Незавершённый снимок старше 48 часов отбрасывается. Это **не** гарантирует обнаружения цены до публикации конкурентами.

## Bright Data Amazon Keyword Search — без Keepa и Amazon Partenaires

Подключён ещё один **собственный канал поиска**: [Bright Data Amazon Products Search](https://brightdata.com/products/web-scraper/amazon), официальный dataset `gd_lwdb4vjm1ehb499uxs`. Он выполняет одноcтраничный поиск по ключевым словам непосредственно на европейских Amazon.fr/.de/.es/.it, получает ASIN, название и EUR-цену и не ждёт публикации на Dealabs.

- **Включение:** добавить в GitHub Actions Secrets `BRIGHTDATA_API_TOKEN`. Keepa и Amazon Creators **не нужны**. На сервере/ПК достаточно этого токена вместе с Telegram-ключами, чтобы запустить `fast_hunter.py`.
- **Бережный режим:** по умолчанию `BRIGHTDATA_SEARCH_PER_DAY=1`, максимум 24 поисковых запуска за календарный месяц. Запросы чередуют четыре рынка и темы интерьера, LEGO, PlayStation и ПК. Это ограничение **не гарантирует** соблюдение 5 000 бесплатных записей: один поиск может вернуть десятки товаров; задавай лимиты расходов также в кабинете Bright Data.
- **Защита от старых данных:** карточки отвергаются, если провайдер отметил снимок старше 48 часов или не дал дату, ASIN, однозначный Amazon URL либо цену в евро. В каталог попадают на 89 минут после сканирования. Дата снимка явно указана в Telegram.
- **Точность скидки:** `initial_price` не является независимо проверенной исторической ценой. Процент снижения на карточке — **только разница с исходной/перечёркнутой ценой**, поэтому уведомление помечается «ПРЕДПОЛАГАЕМАЯ АКЦИЯ», а не «подтверждённая ошибка цены».
- **Ограничение скорости:** один поиск в день подходит для бесплатной разведки, но **не сможет поймать большинство 1–2-минутных ошибок цен**. Для серьёзной охоты нужна оплаченная частота запросов и постоянный воркер. Keepa Deals и прямые повторные проверки ASIN ускоряют нахождение, но тоже имеют задержки.

## Direct price discovery without Amazon Partenaires

**Production-ready adapters (provider accounts required):**

- **Keepa Deals** scans Amazon.fr, Amazon.de, Amazon.es and Amazon.it *directly from Keepa's market price-change index*, independently of user-submitted Dealabs/Mydealz posts. Current Amazon seller price or NEW marketplace price and the actual Keepa 90-day weighted average are strictly separated. The alert includes the data source, last observed price/change time and the fact that checkout/shipping to France are unverified.
- **Bright Data** verifies the exact Amazon product URL/ASIN on high-priority Keepa candidates, only if both the product and the EUR-currency field match. If the verified current price differs by more than 3% from Keepa, the alert is held back. An asynchronous/pending Bright Data snapshot is **not** fabricated as a live check.
- **Amazon Creators** remains optional. Neither Keepa nor Bright Data depends on Amazon Partners. RSS/Pepper remain backups and discovery aids, not the only source.
- **Keepa budget:** requests to the Deals endpoint cost 5 Keepa tokens each. Default `KEEPA_MAX_DEAL_QUERIES_PER_DAY=64`, spread automatically across the full UTC day, so hourly API use does not exhaust the entire quota by morning. A higher quota can be chosen only with a suitable Key/plan. Calls are made only when a Keepa API key exists. `KEEPA_DEAL_QUERIES=1` limits each request batch; no planned requests without a key.
- **Bright Data budget:** one exact-product check per scan (`BRIGHTDATA_PER_SCAN=1`) only when a token is configured, with automatic caps of 80 requests/day and 3,200 requests/month and no rechecking the same product more than once in four hours. These are **our** caps, not provider-side billing controls; the owner's Bright Data billing dashboard should also impose spending limits. No paid requests without a token.
- **Speed:** direct data changes can be checked on scheduled five-minute GitHub Actions runs, but GitHub can be delayed and Keepa itself may update prices later than Amazon. For a permanently running process see `fast_hunter.py` / `docker-compose.fast-hunter.yml`. A 1–2 minute price glitch is not guaranteed to be detected even with fast polling or a paid provider.

**Secrets:** GitHub → [Settings > Secrets and variables > Actions](https://github.com/makeevmua/amazon-diamond-hunter/settings/secrets/actions) → add `KEEPA_API_KEY` and optionally `BRIGHTDATA_API_TOKEN`. Do not paste keys into this repo, chatbot messages, or `preferences-draft.json`. Adding **at least one valid provider API key** is the missing activation step. An empty key disables that provider completely. Keepa access requires a separate paid subscription; Bright Data offers a limited free trial/tier according to its current terms.

**Source documentation:** [Keepa Deals API](https://keepa.com/api-docs/deals.html); [Keepa Deal Object](https://keepa.com/api-docs/deal-object.html); [Bright Data Amazon API](https://brightdata.com/products/web-scraper/amazon). These data sources are **not** first-party Amazon APIs, but they observe Amazon product pages/prices independently from discount forums.

## Amazon-first Hunter — прямой поиск и оперативные уведомления (2026-10-21)

**Новый источник:** официальный Amazon Creators API `SearchItems` ищет новые товары непосредственно в Amazon.fr/.de/.es/.it по сменяющимся запросам (SSD, PlayStation, игры ПК, комплектующие, LEGO, интерьер, Apple и др.). Дополнительный `GetItems` повторно проверяет до 10 точных ASIN в запросе. ASIN из публикаций форумов и Amazon-поиска автоматически добавляются в *список наблюдения*. Обнаружение цены не зависит от того, опубликовал ли её кто-то в Dealabs. Полного перебора миллионов Amazon-товаров нет, поэтому **все короткие ценовые ошибки не гарантируются**.

**Для реальной работы Amazon-first обязателен разрешённый доступ:** Amazon Associates с одобренным Creators API, Credential ID + Secret и Partner Tag для каждого включённого рынка. По документации Amazon порог доступа включает 10 квалифицированных продаж за последние 30 дней; невозможно обещать беспрепятственный бесплатный API для нового аккаунта. Секреты добавить в GitHub → [Settings → Secrets and variables → Actions](https://github.com/makeevmua/amazon-diamond-hunter/settings/secrets/actions):
- `AMAZON_CREATORS_CLIENT_ID`
- `AMAZON_CREATORS_CLIENT_SECRET`
- `AMAZON_PARTNER_TAG_FR`, `AMAZON_PARTNER_TAG_DE`, `AMAZON_PARTNER_TAG_ES`, `AMAZON_PARTNER_TAG_IT` (каждый используемый рынок).

Без этих ключей бот **не делает прямых запросов к Amazon**, а сканирует доверенные сообщества. Наличие кода и 100% локальных тестов не означает доступности API в твоём аккаунте. Нельзя безопасно и бесплатно изобрести эти ключи.

**Расписание GitHub Actions:** основной полный сбор RSS + прямые запросы происходит каждую четверть часа (07/22/37/52). В промежуточные минуты GitHub запускает быстрый сбор с шагом **5 минут** (02/07/12/17/22/27/32/37/42/47/52/57): при наличии API-ключей — Amazon напрямую; без них — только 6 самых быстрых публичных RSS, не все 24. Задержки GitHub Actions возможны; это **не гарантия пяти минут и не решение для ошибок на 1–2 минуты**.

**Для близких к реальному времени оповещений** добавлен самостоятельный сервис `fast_hunter.py`: при наличии ключей и постоянно работающего ПК/VPS/мини-сервера он каждые 60–3600 секунд (по умолчанию 90) обновляет ограниченное число Amazon-поисков и известных ASIN и отправляет Telegram напрямую. Настройку частоты согласовывай с API-квотой. Для установки через Docker:

```bash
cp .env.hunter.example .env.hunter
# Заполнить ключи и TELEGRAM_BOT_TOKEN/TELEGRAM_CHAT_ID
docker compose -f docker-compose.fast-hunter.yml up -d --build
docker compose -f docker-compose.fast-hunter.yml logs -f
```

Секреты в файле `.env.hunter` исключены из git, состояние воркера хранится в отдельном Docker volume. Если 90-секундный процесс работает на домашнем ПК, отключение ПК/сна остановит мониторинг. Мгновенный охват всех маркетплейсов Amazon даже на этом интервале **невозможен** при ограниченном бюджете поисковых запросов.

**Качество цен и безопасность:** в Telegram Amazon-first отдельно помечается как «Amazon Creators API», с временем наблюдения в отчётах сканирования; цена — текущее featured NEW предложение из API, а не доказанная финальная цена и не обязательно продавец Amazon. Разница с `savingBasis` — референс Amazon, не реальное падение рынка. Для детекции фактического изменения цены бот хранит короткую временную серию собственных недавних проверок (не дольше 55 минут из-за часового лимита кэширования Amazon) и сообщает о значительных изменениях. На сайте первичные данные прямых предложений живут **до 58 минут после последней проверки**, чтобы не показывать старые ценники. Доставка во Францию и корзина не проверяются; для независимой истории сохраняется опциональный Keepa API.

Ссылки: [официальная документация Creators API](https://affiliate-program.amazon.com/creatorsapi/docs/en-us/api-reference/operations/search-items), [GetItems](https://affiliate-program.amazon.com/creatorsapi/docs/en-us/api-reference/operations/get-items), [правила кеширования](https://affiliate-program.amazon.com/creatorsapi/docs/en-us/concepts/best-programming-practices), [ограничения Amazon Associates](https://partenaires.amazon.fr/help/operating/policies/).


## Версия Production — долговременная база, фильтры, цена с источником

- **Плановый поиск**: Pepper GraphQL включён в регулярном сканировании (RSS остаётся резервом); его доступность не гарантируется.
- **Резервная копия**: файлы `catalog.sqlite` и `seen.json` восстанавливаются из ветки [diamond-data](https://github.com/makeevmua/amazon-diamond-hunter/tree/diamond-data), когда GitHub cache недоступен. Снимок отправляется на отдельную ветку после первого реального запуска, вручную и в четыре UTC-часовых окна в сутки. Для этого `GITHUB_TOKEN` в workflow имеет `contents: write`; GitHub может запретить запись политиками репозитория, поэтому ошибки снимков пишутся в журнал и кэш остаётся резервным вариантом. Ветка **публичная**: в неё не записываются ключи Keepa или Telegram, но сохраняются публичные объявления и техническая история уведомлений.
- **Сайт**: избранное хранится в `localStorage` браузера (без аккаунта, не синхронизируется между устройствами), фильтр свежести (48 ч / 7 дней), вкладка источника Keepa, чёткая маркировка любых рекламных/исторических цен и сохранение поисковых/категориальных фильтров. Избранное пропадает при очистке данных браузера.
- **Сравнение по ASIN между четырьмя странами**: если один ASIN найден в публикациях о нескольких рынках, сайт показывает ссылки и *заявленные внешними публикациями* цены на других Amazon, не смешивая ASIN разных товаров. Появление одинакового ASIN само по себе не гарантирует одинаковую комплектацию, продавца, наличие или доставку во Францию; цена не сравнивается с финальным чеком.
- **История цен объявления**: в SQLite сохраняются только *реальные изменения суммы, указанной внешней публикацией*. Повторное чтение той же цены не создаёт фиктивную «историю цен Amazon».
- **Keepa API (опционально)**: если у владельца есть действующий платный доступ, добавить `KEEPA_API_KEY` в [Actions Secrets](https://github.com/makeevmua/amazon-diamond-hunter/settings/secrets/actions), не в код. Тогда бот проверяет ограниченное число точных ASIN один раз в сутки, сохраняя тип цены (Amazon / Marketplace New), 90-дневную сравнительную среднюю при достаточной истории и время данных. **Keepa не проверяет финальную корзину, доставку во Францию, продавца и условия скидочного купона.** Без этого секрета данные Keepa не появляются и система ничего не выдумывает.
- **Автоматические проверки**: модульные тесты, сухая проверка источников при обновлении кода, публикация HTML/CSV/JSON. Реальные уведомления Telegram отправляются только плановым/ручным запуском, не тестовыми push-сканами.


Telegram-бот за **0 €/мес.**, который ищет **кандидатные** скидки: от **25% на интерьер и декор**, от **50%** на остальные выбранные категории, от **80%** на узнаваемые бренды вне категорий — на Amazon.fr, Amazon.de, Amazon.es, Amazon.it через публичные RSS. Стандартная проверка примерно раз в 15 минут; вечерний отчёт около **21:00 Europe/Paris**.

> **Важно:** найденный процент — **заявление из внешней публикации, не доказанная реальная экономия**. Бот НЕ умеет в бесплатной версии проверять цену за последние 30–90 дней, состояние/продавца на Amazon или стоимость доставки в FR. Он всегда пишет «НЕ ПОДТВЕРЖДЕНО». Предложений может не быть.

## Скоуп товаров: PlayStation/ПК да, Xbox нет; Samsung только SSD

**Xbox полностью исключён** из Telegram и каталога: приставки, игры, подписки и специализированные аксессуары. **PlayStation, PC, Nintendo, их игры и комплектующие остаются**. Samsung допускается только для SSD/NVMe, в том числе портативных Samsung SSD. Остальные товары Samsung (Galaxy, смартфоны, планшеты, телевизоры, наушники, аксессуары и техника) не публикуются. Фильтр применяется к заголовкам новых объявлений и очищает старые неподходящие записи из SQLite на каждом запуске; это анализ названий, поэтому редкая неоднозначная карточка может потребовать ручной проверки. Случайные упоминания Xbox/Samsung в описании другого товара по возможности не блокируют его.

## Дополнительные бесплатные источники

По идее открытых deal-агрегаторов к исходным 16 потокам добавлены 6 тематических Dealabs RSS: `jardin-bricolage`, `jeux-jouets`, `sante-et-cosmetiques`, `accessoires-gadgets`, `animaux`, `culture-divertissement`. Они повышают охват интерьера, LEGO/игрушек, ухода, гаджетов и прочего. Проверка параллельная; недоступные ленты пропускаются и отображаются в логах, поэтому **22 источника не означает 22 постоянно работающих источника**.

Добавлен **неофициальный экспериментальный Dealabs Pepper GraphQL** (идея из [FaserF/ha-pepper](https://github.com/FaserF/ha-pepper), проект с MIT-лицензией). При плановом сканировании он пытается анонимно прочитать до 60 свежих объявлений, извлечь заявленную цену и дополнить RSS, не повторяя одну и ту же ссылку. Используются только чтение публичных объявлений и ограниченное число запросов; CAPTCHA, приватные аккаунты и обход блокировок не применяются. **Pepper может перестать работать или отказать в доступе в любой момент; если запрос не выполнен, базовый RSS-сканер продолжает работать.** Данные Pepper — заявления сообщества, не подтверждение цены Amazon. При необходимости можно отключить через `PEPPER_GRAPHQL_ENABLED=false` в окружении или в workflow.

## Ещё один рынок: Германия

Включены **Amazon.de**, дополнительная лента [Brickset Amazon.de](https://brickset.com/feed/amazon/de) и публичный mydealz.de RSS. Их доступность определяется при каждом плановом запуске. Немецкие заголовки распознаются по ключевым словам из категорий ПК, техники и интерьера; по-прежнему не считаем весь каталог Amazon просканированным. Доставка в Францию, цена корзины, продавец, вилка и гарантия не проверены.

На сайте теперь отображается число работающих RSS и количество публикаций из Pepper — это данные *последнего сканирования*, а не постоянная гарантия доступности источника.

### Дополнительные источники без платных API

Бот теперь параллельно загружает ленты (максимум 6 одновременно), удаляет повторные ссылки на одно объявление и продолжает сканирование, если часть RSS недоступна.

Дополнительные публичные RSS можно подключить без изменения кода: [Settings → Secrets and variables → Actions → Variables](https://github.com/makeevmua/amazon-diamond-hunter/settings/variables/actions) → **New repository variable** → имя `EXTRA_RSS_FEEDS`, значение — список **реально существующих RSS URL** через запятую, точку с запятой или новую строку. Можно добавить до 24 дополнительных URL. Разрешены только HTTPS-ленты от Dealabs, Chollometro, QuantoSpendo, Les Numériques и Brickset, без Великобритании и США. Например, если у издателя работает тематический URL, его можно добавить сюда; доступность будет отражена в логах `FEED OK` / `FEED unavailable`.

Это расширение **не сканирует напрямую Amazon**, не использует закрытый GraphQL или платные сервисы, не обещает обнаружить все ошибки цен. Пустой или недействующий RSS не добавит товаров — проверяй реальные результаты запусков.

## 💎 База находок — новая функция

Помимо отдельных уведомлений Telegram бот ведёт **архив объявлений** в `catalog.sqlite`: подходящие товары даже с недостаточной для Telegram скидкой, оригинальные ссылки, описание, категория, фото при наличии, рекламная цена, источник, даты первого и последнего наблюдения. Каждый RSS-пост фиксируется отдельно; повторные проверки не создают дубликаты.

После каждого запуска GitHub Actions формируется архив **`diamond-findings-<run_id>`** со следующими файлами:

- `catalog_export/index.html` — автономная поисковая страница с миниатюрами, сортировкой, фильтром категории и статуса; открывается локально в браузере;
- `catalog_export/finds.csv` — таблица для Excel, Google Sheets и LibreOffice;
- `catalog_export/finds.json` — машинные данные со статусами, датами, источниками и ценами;
- `catalog.sqlite` — локальная база SQLite с повторными наблюдениями.

**Как открыть:** [GitHub Actions — Amazon Diamond Hunter FREE](https://github.com/makeevmua/amazon-diamond-hunter/actions/workflows/diamond-hunter.yml) → открыть последний успешный запуск → **Artifacts** → скачать `diamond-findings-...` → распаковать и открыть `catalog_export/index.html`.

Ключевой принцип: *«публикация в базе» ≠ «проверенная скидка»*. Цена из статьи с таблицей разных продавцов никогда не считается подтверждённой ценой Amazon. В частности, архив различает `mixed_merchants_unverified` и `unverified_public_offer`. База **не обходит все карточки Amazon**, не подтверждает цену, доставку, наличие или продавца.

GitHub Actions кеширует `catalog.sqlite` между рабочими запусками с ограничениями best-effort; архив хранится **3 дня**, после чего GitHub автоматически удаляет его. Сам каталог ограничен 6000 публикациями за последние 60 дней, экспортирует последние 1500 строк. Для постоянного архива потребуется отдельное бесплатное хранилище или периодически скачивать ZIP. На push-запусках сохранённая база теперь восстанавливается из кэша, если он доступен; тестовый прогон не обновляет состояние Telegram-уведомлений и не сохраняет этот кэш. Накопление истории происходит на плановых и ручных запусках. Кэш может исчезнуть по правилам GitHub.

## Фото в Telegram

Бот старается приложить **картинку конкретной публикации** из RSS (enclosure / media:thumbnail / изображение внутри описания) или оригинальной страницы (`og:image`). Для недостающих фотографий предусмотрено не больше **трёх дополнительных запросов к исходным статьям за запуск**.

- С картинкой отправляется Telegram `sendPhoto`, подпись, предупреждение об отсутствии независимой проверки и прежние кнопки перехода.
- Фото является иллюстрацией от автора публикации, **не подтверждённым изображением точного варианта товара Amazon**.
- Если фото отсутствует, не поддерживается, недоступно, слишком длинная подпись либо Telegram не принимает его, отправляется **полное текстовое сообщение**. Подходящее фото не выдумывается и не скачивается из случайной выдачи.
- Только HTTPS URL без учётных данных, IP-адресов и локальных hostnames допускаются как кандидаты для изображения.

## Фильтры

Настройки лежат в [preferences-draft.json](preferences-draft.json), теперь применяются к бесплатному сканеру в той мере, в какой доступны данные:

- девять категорий: ПК, игровые товары, консоли, видеоигры, VR, смартфоны, ТВ/аудио, техника для дома, выдающиеся сделки других категорий;
- любые цены; интерьерные товары и декор от **25%**, другие выбранные категории от **50%**, «неожиданный алмаз» известного бренда от **80%** — всё по заявлениям источников; предпочтение Bauhaus, Nordic, необычной мебели и декору;
- распознаёт несколько форматов ссылок Amazon, кодированные ссылки в HTML/JSON/RSS и короткие ссылки Amazon, когда возможно безопасно раскрыть адрес;
- пропуск явных б/у, восстановленных и no-name предложений (текстовая фильтрация, не проверка продавца);
- основные уведомления только при найденной прямой ссылке на карточку `https://amazon.fr/dp/ASIN`, `https://amazon.es/dp/ASIN`, `https://amazon.it/dp/ASIN`;
- дополнительный режим **«Перспективная находка»**: если редакционная страница Dealabs / Les Numériques доступна, но прямой Amazon URL не найден, до **3** подобных сообщений за запуск отправляются с **исключительно ссылкой на публикацию**. Магазин может быть не Amazon; реальная цена и доставка не проверены. Прямые ссылки Amazon имеют приоритет. Каждая ссылка защищена от повторов; позже найденный прямой Amazon URL может вызвать отдельное уведомление;
- кросс-граничные предложения помечаются «доставка во Францию не проверена»;
- защита от повторов через GitHub Actions cache: повторное уведомление при увеличении заявленной скидки на 10 процентных пунктов или, **только для находок без процента**, при снижении указанной в публикации цены минимум на 20% и 5 € по сравнению с ранее отправленной находкой. Эти значения — не live-цены Amazon;
- кнопки Telegram **«Открыть на Amazon»** и **«Исходное предложение»**. Для публикации без подтверждённого Amazon URL — только кнопка **«Проверить находку»**. Используются только разрешённые HTTPS-адреса;
- запись `seen.json` через временный файл с атомарной заменой, чтобы снизить риск повреждения локального кэша при прерывании. Сохранность GitHub Actions cache по-прежнему не гарантирована.

## Ранний поиск без готового процента скидки

Три вида сигналов дополняют обычные сообщения о скидках:

- **⚠️ Возможная ошибка цены**: в заголовке свежей публикации есть явная фраза вроде *erreur de prix*, *error de precio*, *errore di prezzo*, *price glitch* и **ровно одна цена в евро**, а также совпадение с выбранной категорией или брендом. **Это неподтверждённый сигнал**, не доказанная ошибка.
- **👀 Наблюдение за ценой**: рекламная публикация об интересующем бренде/стиле с одной конкретной ценой в заголовке и **прямой ссылкой на карточку Amazon**, даже без процента скидки. Максимум **2 на запуск, 6 за парижский день**.
- **📉 Снижение относительно прошлых публикаций**: сравнение с минимум двумя отдельными более старыми публикациями об **одном точном ASIN и той же площадке**, разнесёнными не менее чем на сутки; минимум 40% ниже медианы прошлых рекламных цен. Это **не историческая цена Amazon** и не независимое доказательство экономии. История неполная, хранится в best-effort GitHub Actions cache.

Для срочных подозрений действует лимит **2 на запуск и 12 за день**. Общий лимит отправки — 5 уведомлений за проверку. Защита от повторов сохраняется.

Процентные пороги продолжают действовать: 25% для дизайна/интерьера, 50% для остальных категорий, 80% для «неожиданных алмазов». В сообщениях без указанного процента бот не придумывает экономию и не объявляет ошибку подтверждённой. Источники — только публичные RSS-публикации; **бот не просматривает автоматически все товары Amazon, не считывает live price и не подтверждает продавца/наличие/доставку**.

## Telegram и GitHub Actions

В **Settings → Secrets and variables → Actions** должны быть два секрета:

- `TELEGRAM_BOT_TOKEN` — секретный токен BotFather;
- `TELEGRAM_CHAT_ID` — **личный** числовой ID получателя, не ID бота.

Токен никогда не вставляй в публичный код. Боту нужно отправить `/start` один раз.

**Actions → Amazon Diamond Hunter FREE → Run workflow** — ручной запуск: тесты, пробное сообщение и сканирование Telegram. На каждое изменение кода GitHub теперь запускает **тесты и сухой сетевой скан RSS (`DRY_RUN=true`)** — без реальных Telegram-уведомлений и без записи cache state. Если источник недоступен, его статус видно в логах. Регулярное сканирование и обновление состояния выполняются по расписанию или при ручном запуске.

Плановый запуск каждые ~15 минут может задерживаться или пропускаться GitHub Actions. Дополнительные расписания в 19:00 и 20:00 UTC помогают отправить вечерний отчёт около 21:00 по Парижу с учётом перехода на летнее/зимнее время. Если GitHub не запустит job в нужный час, отчёт может задержаться или не прийти.

## Как читается отчёт

Содержит число запусков, проверенных RSS-публикаций (с повторами), найденных **кандидатов** (не уникальных товаров), число отправленных уведомлений и рынки. Если подходящих предложений не было, пришлёт нулевой отчёт. Статистика хранится в Actions cache, который не даёт гарантии постоянного хранения данных.

Извлечение URL может не сработать, когда сайт скрывает адрес за JavaScript/авторизацией/редиректом. Тогда бот пропускает предложение и отмечает пропуск в логах; он никогда не выдумывает ссылки или цены. До 20 страниц публикаций за запуск анализируются дополнительно для поиска адреса продавца. Если страница содержит ссылки на несколько разных товаров Amazon, она считается неоднозначной и не отправляется как скидка на один товар. В до 8 статьях за запуск бот дополнительно проверяет метаданные заголовка/описания на наличие явной скидки. Это не проверка актуальных цен.

## Диагностика поиска

В логах GitHub Actions есть `SCAN FUNNEL`: сколько публикаций было старых, неподходящих, ниже порога, без прямого Amazon URL и сколько прошло фильтр. `UNRESOLVED` показывает до трёх публичных ссылок, которым не хватило подтверждённого товарного URL. Строки тестов с фиктивными кандидатами — не реальные Telegram-уведомления. Не путайте заявленное снижение от рекомендованной цены с реальной экономией относительно последних 30 дней.
